# Hermes Agent 使用指南 03：交互界面篇 - CLI 使用与命令操作

## 一、命令行界面概述

### 1.1 CLI 界面特点与优势

Hermes Agent 的命令行界面（CLI）是与系统交互的主要方式，它继承了终端的简洁高效特性，同时提供了丰富的交互能力。CLI 界面的设计理念是让用户能够以最直接的方式与 Agent 沟通，无需依赖图形界面或鼠标操作，所有操作都可以通过键盘完成。对于技术用户来说，CLI 提供了更好的可脚本化和自动化能力，可以将常用的操作序列编写成脚本一键执行，极大提升工作效率。另一个显著优势是远程访问能力，无论你通过 SSH 连接到服务器还是在本机终端中操作，都能获得一致的体验。CLI 还占用极少的系统资源，在资源受限的环境中也能流畅运行。此外，所有交互都有清晰的文本记录，便于审计和问题排查。

### 1.2 启动与退出方式

启动 Hermes Agent 的 CLI 界面非常简单。在终端中直接输入 `hermes` 命令即可启动，系统会加载配置、初始化组件，然后显示欢迎信息和命令提示符。如果你希望在启动时直接加载某个会话，可以使用 `hermes --session <session_name>` 参数指定会话名称。通过 `--profile <profile_name>` 参数可以在启动时切换到指定的配置 Profile。对于需要调试的场景，`--verbose` 参数会输出详细的运行日志，帮助你了解系统内部的运作过程。退出 CLI 界面有多种方式：输入 `exit` 或 `quit` 命令可以安全退出；使用快捷键 `Ctrl+D` 发送 EOF 信号也能退出；`Ctrl+C` 可以中断当前正在执行的操作。安全退出时系统会保存当前状态和对话历史。

### 1.3 界面布局与组成

Hermes Agent 的 CLI 界面采用清晰的布局设计，各个区域承担不同的信息展示功能。顶部通常显示欢迎信息和系统状态，包括当前使用的模型、配置的 Profile 以及任何需要注意的提示消息。主交互区域是输入和输出显示的地方，用户输入显示在左侧提示符后，Agent 的响应显示在下方。状态栏位于底部或侧边，显示当前会话的状态、上下文长度估计、已使用的 Token 数量等信息。某些版本还支持分屏显示，左侧显示对话历史，右侧显示当前正在进行的交互或工具执行输出。多行输入时，界面会自动处理换行显示，保持良好的可读性。你可以通过配置调整界面的颜色方案和显示元素，满足个人偏好。

## 二、基本命令系统

### 2.1 帮助与信息命令

掌握帮助命令的使用是熟练操作 Hermes Agent 的第一步。在 CLI 中输入 `help` 或使用问号 `?` 可以显示所有可用命令的列表，按类别组织并附有简要说明。对于特定命令的帮助，可以使用 `help <command_name>` 或 `<command_name> --help` 的格式，例如 `help model` 会显示模型相关命令的详细说明。`info` 命令显示当前系统的完整配置和状态信息，包括模型名称、提供商、API 端点以及各组件的运行状态。`status` 命令提供更精简的状态概览，显示关键指标如连接状态、会话时长和请求计数。`version` 命令显示 Hermes Agent 的版本号和构建信息，当你需要报告问题或检查更新时非常有用。`whoami` 命令显示当前用户信息和权限级别，帮助确认系统识别的身份。

### 2.2 会话管理命令

会话管理是日常使用中的核心操作之一。`new` 或 `/new` 命令创建一个新的对话会话，系统会清空当前上下文并开始一段全新的对话。`sessions` 命令列出所有已保存的会话，包括会话名称、创建时间和最后活动时间。`load <session_name>` 命令加载指定的已保存会话，恢复到之前的对话状态。`save [session_name]` 命令保存当前会话状态，如果不指定名称则使用当前会话的名称。你可以通过 `rename <old_name> <new_name>` 重命名会话，通过 `delete <session_name>` 删除不再需要的会话。`export` 命令允许将对话历史导出为多种格式，包括纯文本、Markdown 和 JSON，便于分享或存档。定期清理不再需要的会话可以保持系统整洁，也能节省存储空间。

### 2.3 模型相关命令

在 CLI 中可以直接管理和切换 AI 模型。`model` 或 `/model` 命令显示当前使用的模型信息。`model list` 或 `models` 命令列出所有已配置的可用模型，以及它们的基本参数和支持的功能。切换模型使用 `model use <model_name>` 命令，例如 `model use gpt-4` 可以切换到 GPT-4 模型。`model info <model_name>` 命令显示特定模型的详细信息，包括上下文长度限制、支持的特性等。通过 `model set temperature <value>` 可以调整当前模型的温度参数，`model set max_tokens <value>` 设置最大生成长度。`model default <model_name>` 命令将指定的模型设置为默认模型，以后启动时自动使用。对于需要临时修改模型参数的场景，这些即时生效的命令比编辑配置文件更加方便快捷。

### 2.4 上下文与历史命令

上下文管理对于维持长时间对话的连贯性至关重要。`context` 或 `/context` 命令显示当前对话的上下文状态，包括已使用的 Token 数量、距离上下文限制还有多少空间以及最近的对话轮次摘要。`context reset` 命令清除当前上下文但保留会话，允许开始新的对话方向而不丢失会话本身。`context compact` 命令触发上下文压缩，将历史信息浓缩为更紧凑的表示，释放上下文空间供继续对话使用。`history` 或 `hist` 命令显示当前会话的完整对话历史，每条记录都带有时间戳。`search <keyword>` 命令在历史记录中搜索包含特定关键词的对话，便于找回之前讨论过的内容。理解并善用这些上下文管理命令，可以让你在长对话场景中保持良好的交互体验。

## 三、工具调用与执行

### 3.1 工具调用的基本流程

在 Hermes Agent 中，工具是 Agent 与外部世界交互的桥梁。当你发出一个请求时，Agent 会分析你的意图，判断是否需要调用工具以及调用哪些工具。工具调用遵循标准化的流程：首先 Agent 生成调用指令，包含工具名称和参数；然后系统验证调用的合法性，包括权限检查和参数校验；接着执行工具并将结果返回给 Agent；最后 Agent 整合工具输出生成最终回复。整个过程对用户是透明的，但你可以通过配置决定是否显示工具调用的详细信息。默认情况下，系统会在执行工具时显示简要的状态提示，如「正在搜索网页...」或「正在读取文件...」。如果需要查看更详细的信息，可以使用 `/verbose` 命令开启详细输出模式。

### 3.2 工具执行的控制

用户对工具执行有多种控制手段。最直接的控制是在工具执行前进行确认，当启用 `confirm_tools` 配置时，系统会在执行可能产生影响的操作前提示用户确认。常见的确认场景包括写入文件、执行命令、发送网络请求等，你可以在配置中自定义需要确认的工具类别。对于可能耗时较长的操作，可以使用超时设置来控制最大执行时间，避免无限等待。你也可以使用 `/cancel` 命令取消正在执行的操作。另一种控制方式是限制工具的使用权限，某些敏感工具可能需要特定权限才能使用，关于权限管理的内容将在后续章节详细介绍。对于频繁使用的工具组合，可以将它们保存为工具集，通过简短的命令快速调用。

### 3.3 工具输出与结果处理

工具执行完成后，结果会展示在界面上并纳入后续的对话上下文。不同类型的工具有不同的输出格式：文件读取工具会显示文件内容；搜索工具会显示搜索结果摘要；代码执行工具会显示运行输出和执行时间统计；网络请求工具会显示响应状态和关键内容。你可以通过配置调整输出显示方式，例如限制输出长度以避免大量内容刷屏，启用语法高亮使代码更易读，或者将输出重定向到文件而不是显示在终端。工具执行过程中可能产生错误，常见错误包括参数错误、权限不足、网络超时等，系统会清晰显示错误信息和建议的解决方法。某些工具支持增量输出，可以在执行过程中实时显示进度，适用于耗时较长的操作。

## 四、快捷键与效率技巧

### 4.1 编辑与导航快捷键

熟练使用快捷键可以显著提升 CLI 操作效率。在输入方面，常用的快捷键包括 `Ctrl+A` 跳到行首、`Ctrl+E` 跳到行尾、`Ctrl+W` 删除光标前一个单词、`Ctrl+U` 删除整行输入。历史命令导航使用上下箭头键可以浏览之前执行过的命令，`Ctrl+R` 启动反向搜索，输入关键词快速查找匹配的历史命令。`Ctrl+L` 清屏，相当于执行 `clear` 命令。当需要输入多行内容时，在行尾输入反斜杠 `\` 可以续行，界面会显示延续提示符。Tab 键提供自动补全功能，涵盖命令名称、参数值、文件名和会话名称等，按两次 Tab 可以显示所有可能的补全选项。学会这些快捷键后，你的手指可以始终保持在键盘主区域，无需频繁移动到方向键或鼠标。

### 4.2 输出浏览快捷键

当 Agent 输出内容较多时，需要使用快捷键来高效浏览。`Space` 键向下翻页，`b` 键向上翻页（backward），这是浏览长输出的标准方式。`g` 键跳到输出开头，`Shift+G` 或 `G` 跳到输出结尾。按 `/` 启动搜索模式，输入关键词后 `n` 跳到下一个匹配位置，`N` 跳到上一个匹配位置。如果只想看输出的最后几行（最新内容），可以使用 `Ctrl+End` 或 `End` 键。`q` 键退出分页模式，返回交互状态。对于需要仔细阅读的长输出，建议先按 `s` 将输出保存到临时文件，这样即使退出当前界面也能随时查阅。这些快捷键遵循多数 pager 程序（如 less、more）的惯例，学习成本低且用途广泛。

### 4.3 效率提升技巧

除了快捷键，还有一些使用技巧可以帮助你更高效地使用 Hermes Agent。首先是命令别名，在配置中为常用命令创建简短别名，例如将 `model use gpt-4` 设置别名为 `m4`，将 `context compact` 设置别名为 `cc`。其次是使用管道和重定向，将命令输出传递给其他程序处理，例如 `sessions | grep today` 查找今天的会话。`!!` 代表上一条命令，可以快速重复执行或在其基础上修改。对于复杂任务，使用多行输入可以清晰地表达你的需求，长文本或代码块可以直接粘贴而不需要逐行输入。`Ctrl+C` 的灵活运用也很重要：一次 `Ctrl+C` 取消当前输入，两次 `Ctrl+C` 强制终止操作。此外，充分利用 Tab 补全和历史搜索可以大大减少输入量，这些都是提升效率的关键习惯。

## 五、高级交互功能

### 5.1 多模态输入支持

Hermes Agent 支持多种形式的输入，不仅仅是纯文本。对于图片输入，你可以通过 `![description](path/to/image.png)` 的语法在消息中嵌入图片，Agent 会分析图片内容并结合你的问题给出回应。支持粘贴剪贴板中的图片数据，这在截屏分享时特别有用。文件输入方面，你可以直接在消息中引用本地文件路径，系统会读取文件内容并纳入上下文，例如「请分析这个文件 `/home/user/data.csv`」。对于代码文件，系统会自动识别语言并进行适当的格式化处理。语音输入是另一个便捷功能（如果启用），可以使用 `~voice` 命令进入语音输入模式，说话后系统会自动转录为文字。这些多模态支持大大扩展了交互的可能性，让你可以用最自然的方式与 Agent 沟通。

### 5.2 代码块与格式化

在需要输入代码或格式化文本时，Hermes Agent 支持标准的 Markdown 代码块语法。行内代码使用单反引号包裹，如 `` `variable` ``，多行代码块使用三个反引号包裹，并可以指定语言获得语法高亮。当你在输入中包含代码块时，系统会保持格式不变；当 Agent 输出代码时，也会自动使用代码块格式便于复制使用。输出的格式化还包括列表、表格、引用块等 Markdown 元素的正确渲染。对于 JSON、XML、YAML 等结构化数据，系统会进行适当的格式化缩进。数学公式支持 LaTeX 语法，可以使用 `$inline$` 和 `$$block$$` 分别插入行内和独立公式。这些格式化功能让交互体验更加丰富和专业，特别适合技术文档撰写和代码协作场景。

### 5.3 会话间上下文传递

在实际使用中，经常需要在不同会话之间传递上下文或延续某个工作。Hermes Agent 提供了多种机制支持这种需求。最基本的方式是在新会话开始时使用提示词描述之前的对话背景，让 Agent 了解前因后果。更高级的方式是使用会话链接功能，通过 `/link <session_name>` 命令将指定会话的上下文片段引入当前会话，这个功能特别适合需要跨越多个主题但在某些方面有关联的场景。模板功能允许你保存常用的提示词结构，在新会话中快速加载，例如创建一个代码审查模板，每次进行代码审查时直接加载而不需要重新编写。变量机制也很有用，你可以在一个会话中定义变量，然后在后续的提示词中引用这些变量，实现参数的统一管理和批量修改。

## 六、配置与个性化

### 6.1 界面显示配置

Hermes Agent 允许深度定制 CLI 界面的显示方式。颜色主题配置让你可以选择界面各元素的颜色方案，系统内置了多种预设主题，也支持自定义颜色代码。提示符样式配置可以修改命令输入前的提示符格式，默认显示模型名称和会话状态，你可以根据喜好添加时间、路径、工作目录等信息。输出格式化配置控制内容的显示方式，包括代码高亮主题、表格样式、Markdown 渲染选项等。语言本地化配置让你可以选择界面的显示语言，目前支持中文和英文。日志详细程度配置决定系统输出信息的多少，从静默模式到调试模式多个级别可选。分页器配置控制内容较多时的显示方式，包括使用的分页程序、每页行数等。通过这些配置项，你可以将界面调整到最符合个人习惯和工作需求的状态。

### 6.2 命令别名与快捷命令

为常用命令创建别名是提升效率的好方法。在配置文件的 `aliases` 部分定义命令别名，例如 `alias.new: model use claude-3`。定义后，在 CLI 中只需输入 `new` 就会执行 `model use claude-3`。别名支持参数传递，使用 `$1`、`$2` 等占位符代表传入的参数，例如 `alias.quickreview: code review $1 with rules $2`。更复杂的场景可以使用 Shell 函数或脚本，将它们放在配置指定的脚本目录中，CLI 会自动识别并允许直接调用。快捷命令特别适合团队协作场景，可以创建团队统一的命令集，通过配置文件分发，确保团队成员使用一致的操作方式。对于需要临时定义的别名，可以使用 `/alias` 命令在当前会话中创建，会话结束后自动清除。

### 6.3 启动脚本与初始化

Hermes Agent 支持在启动时自动执行脚本，实现个性化的初始化流程。启动脚本位于配置目录的 `init` 子目录下，以 `.sh` 为扩展名的脚本会在 CLI 启动后自动执行。你可以在脚本中执行各种初始化操作：显示欢迎信息和每日提示、设置会话变量、检查系统状态、加载特定工具集等。条件启动脚本根据环境或参数有选择地执行，例如只在生产环境加载额外的安全检查，或者只在特定 Profile 激活时执行特定初始化。`on_load` 钩子允许你在加载会话后执行特定操作，例如自动显示会话摘要或执行某个固定的后处理步骤。这些自动化机制让你每次启动 Hermes Agent 时都处于最佳工作状态，无需每次手动设置。

## 七、特殊场景使用

### 7.1 脚本化与批处理

虽然 CLI 主要用于交互式使用，但它也提供了强大的脚本化能力，支持非交互式调用。对于一次性任务，可以直接使用命令行参数执行，例如 `hermes "请解释什么是量子计算"` 会在启动后立即执行查询并输出结果，然后自动退出。批处理模式允许你将多个查询写入文件，使用 `hermes batch <file>` 逐行执行。输出可以通过重定向保存到文件或传递给其他程序处理。对于需要循环处理的场景，可以使用 Shell 脚本包装 Hermes 调用，实现复杂的自动化流程。返回码（Exit Code）机制便于脚本判断执行结果：0 表示成功，非 0 表示出现问题。详细的日志选项可以控制脚本执行时的输出详细程度，确保错误信息能够被正确捕获和处理。

### 7.2 远程与无头模式

Hermes Agent 支持在没有图形界面的环境中运行，非常适合服务器部署和远程访问。无头模式（Headless Mode）通过 `--headless` 参数激活，禁用所有需要交互的功能，如命令补全提示、确认对话框等，专注于命令执行和输出返回。远程访问场景中，通常通过 SSH 连接到服务器，然后在 SSH 会话中启动 Hermes Agent CLI，所有的输入输出都通过 SSH 隧道传输。为了安全起见，在远程环境中应该启用 TLS 加密和身份认证。另一个有用的模式是守护进程（Daemon）模式，Hermes Agent 在后台持续运行，通过 API 或 Unix Socket 接收请求，这种方式适合需要频繁调用的服务场景。WebSocket 接口支持允许从网页或其他客户端实时交互，提供了另一种灵活的远程使用方式。

### 7.3 协作与会话共享

Hermes Agent 提供了会话协作功能，方便团队共享和讨论。`share` 命令生成一个安全的分享链接，接收者可以通过链接查看（只读）完整的对话内容，但无法修改或继续对话。分享时可以选择匿名模式或要求身份验证，后者会记录查看者的身份信息。实时协作模式允许多人同时参与同一个会话（需要相应的权限和配置），每个参与者的输入都会实时同步显示，其他人可以立即看到并回应。权限管理确保协作者只能执行被授权的操作，例如只读参与者无法调用工具或修改配置。审计日志记录所有协作活动，便于追踪问题和责任归属。这些协作功能让 Hermes Agent 不仅是个人的 AI 助手，也成为团队的知识工作和协作平台。
