# Hermes Agent 使用指南 08：安全机制篇 - 权限管理与安全设置

## 一、安全架构概述

### 1.1 安全设计理念

Hermes Agent 的安全架构建立在纵深防御和多层保护的原则之上。在数字时代，智能代理系统面临多种潜在威胁，包括但不限于未授权访问、数据泄露、恶意工具执行和系统资源滥用。为此，Hermes Agent 构建了一个全面的安全体系，涵盖身份认证、权限控制、资源限制、数据保护和审计追踪等多个维度。安全不是事后添加的补丁，而是从设计之初就被融入到系统的每个组件中。这种理念确保了安全措施不会成为功能的阻碍，而是与系统能力和谐共存，让用户在享受强大功能的同时无需担心安全问题。

### 1.2 安全组件关系

安全体系由多个相互配合的组件构成。认证组件负责验证用户身份，确认是谁在使用系统。授权组件基于认证结果决定用户可以执行哪些操作。凭证管理组件安全存储 API 密钥、密码等敏感信息。沙箱组件隔离工具和插件的执行环境，限制其对系统的访问能力。审计组件记录所有安全相关的事件，供事后分析和合规检查。策略引擎协调这些组件，根据配置的策略做出安全决策。这些组件共同工作，形成一个完整的安全防护网，任何单一环节的失效都不会导致系统完全暴露于风险之中。

### 1.3 安全策略模型

Hermes Agent 采用基于角色的访问控制（RBAC）和基于属性的访问控制（ABAC）相结合的策略模型。基于角色的控制将用户划分为不同角色，如管理员、普通用户和只读用户，每个角色拥有不同的权限集合。基于属性的控制则根据用户属性、资源属性和环境属性做出更细粒度的决策。例如，管理员可以执行任何操作，普通用户只能使用经过批准的工具，只读用户只能查看信息不能执行任何操作。这种双重策略模型既提供了清晰的权限层级结构，又支持灵活的场景化配置，满足从个人使用到企业部署的多种需求。

## 二、身份认证

### 2.1 认证方式

Hermes Agent 支持多种身份认证方式适应不同场景。本地认证使用用户名和密码，适合个人部署和内网环境。API 密钥认证适合程序化访问，使用随机生成的密钥进行身份验证。OAuth2 认证支持与第三方身份提供商集成，如企业 SSO 系统。SSH 密钥认证适用于通过 SSH 远程访问的场景。多因素认证（MFA）可以为高安全性需求添加额外的验证层，如手机验证码或硬件令牌。会话认证维持用户的登录状态，允许在会话有效期内无需重复认证。这些认证方式可以单独使用，也可以组合使用以增强安全性。

### 2.2 用户与角色管理

系统支持多用户环境，每个用户拥有独立的配置、历史和权限。创建用户使用 `hermes user create <username>` 命令，系统会引导设置密码和基本信息。用户列表使用 `hermes user list` 查看，包括用户名、角色、创建时间和最后登录时间。修改用户信息使用 `hermes user update <username>`，可以更改密码、邮箱或基本信息。删除用户使用 `hermes user delete <username>`，会同时删除该用户的所有会话和配置。角色分配使用 `hermes user set-role <username> <role>`，可以将用户设置为管理员、普通用户或自定义角色。角色决定了用户的权限边界。

### 2.3 会话管理

会话管理确保用户认证状态的安全控制。登录使用 `hermes login <username>` 命令，系统会验证凭证并创建认证会话。会话超时可以配置，长时间不活动后系统会自动登出，防止未授权使用。强制登出使用 `hermes session revoke <session_id>`，管理员可以远程终止特定会话。查看活跃会话使用 `hermes session list`，显示所有当前登录的会话信息，包括会话 ID、用户、登录时间和最后活动时间。会话信息泄露检测会监控异常会话活动，如来自新地点或设备的登录。定期审查会话列表，及时终止不再需要的会话是良好的安全习惯。

### 2.4 API 密钥管理

API 密钥用于程序化访问，绕过交互式登录。创建 API 密钥使用 `hermes api-key create [--name <name>]`，系统生成随机密钥并显示，只会显示这一次，之后无法再次查看。列出密钥使用 `hermes api-key list`，显示名称、创建时间和最后使用时间，不显示密钥本身。撤销密钥使用 `hermes api-key revoke <key_id>`，撤销后密钥立即失效。密钥应该安全存储，建议使用密码管理器。定期轮换密钥降低密钥泄露的风险，设置自动过期策略可以强制定期更新。不同用途应该使用不同密钥，便于追踪和撤销。

## 三、权限控制

### 3.1 内置角色与权限

Hermes Agent 定义了多层级的内置角色。管理员角色拥有最高权限，可以执行所有操作，包括用户管理、插件管理和系统配置。普通用户角色可以使用大部分功能，包括对话、工具和基本配置，但不能管理系统级设置和用户。只读用户角色只能查看信息，不能执行任何会修改状态的操作。自定义角色可以根据组织需求定义，继承基础角色的权限并添加特定限制。查看角色的权限使用 `hermes role permissions <role_name>`，会列出该角色拥有的所有权限项。权限项采用资源：操作的形式，如 `tool:execute` 表示执行工具的权限。

### 3.2 细粒度权限配置

除了角色级别的权限，还可以针对具体资源设置细粒度权限。工具权限控制哪些工具可用：`tool:read_file` 允许读取文件，`tool:write_file` 允许写入文件，`tool:run_command` 允许执行命令。操作权限控制敏感操作：`session:delete` 允许删除会话，`config:modify` 允许修改配置。资源权限控制对特定资源的访问：`resource:user_home` 限制只能访问用户主目录。配置权限使用配置文件的 `permissions` 部分：

```yaml
permissions:
  roles:
    user:
      tools:
        - read_file
        - web_search
        - calculator
      actions:
        - session:create
        - session:list
  overrides:
    senior_developer:
      tools:
        - run_python
        - run_command
```

### 3.3 权限继承与覆盖

权限配置支持继承机制简化管理。子角色继承父角色的所有权限，然后在此基础上添加或覆盖。定义角色层级：

```yaml
roles:
  base_user:
    permissions:
      - session:*
      - tool:read_file
  
  developer:
    inherits: base_user
    permissions:
      - tool:run_command
      - tool:run_python
  
  admin:
    inherits: developer
    permissions:
      - user:*
      - config:*
```

覆盖机制允许子角色修改继承来的权限。否定权限（使用 `!` 前缀）可以显式禁用某个权限，优先级高于继承的肯定权限。

### 3.4 权限检查与验证

系统会在执行操作前进行权限检查。用户发起请求时，系统获取用户角色，查询该角色是否有执行操作的权限，如果需要还要检查资源级别的权限。权限检查的详细日志记录在审计日志中，包括请求者、被检查的权限和检查结果。实时权限验证可以使用 `hermes permission check <user> <permission>` 命令，查询用户是否有特定权限。权限验证失败时，系统会返回清晰的错误信息，说明缺少哪个权限。管理员可以使用权限模拟功能（`sudo`）临时以其他用户身份执行操作，常用于故障排查和管理任务。

## 四、资源访问控制

### 4.1 文件系统限制

文件系统访问是最敏感的权限之一，需要严格控制。基本限制是工作目录，用户只能在其工作目录内进行文件操作。路径遍历防护阻止使用 `..` 等方式访问受限目录。文件类型限制可以禁止访问特定类型的文件，如可执行文件或配置文件。操作限制区分只读和读写权限。敏感路径保护禁止访问系统关键目录，如 `/etc`、`/root`、`~/.ssh` 等。配置文件控制文件系统权限：

```yaml
security:
  filesystem:
    work_dir: ~/hermes_workspace
    allow_beyond_workdir: false
    restricted_paths:
      - /etc
      - /root
      - /var/secrets
    max_file_size: 100MB
    allowed_extensions:
      - .txt
      - .md
      - .py
      - .json
```

### 4.2 网络访问限制

网络访问同样需要谨慎控制。出站连接白名单限制只能访问指定的域名和 IP 地址。连接端口限制只允许访问常用端口，如 80、443 等。协议限制可以选择性禁用某些协议，如禁用 FTP、Telnet 等不安全的协议。IP 黑名单阻止访问已知的恶意地址或地区。配置网络限制：

```yaml
security:
  network:
    outbound_whitelist:
      - api.openai.com
      - api.anthropic.com
      - github.com
    allowed_ports:
      - 80
      - 443
    blocked_ips:
      - 10.0.0.0/8
      - 192.168.0.0/16
    max_connections: 100
```

### 4.3 命令执行限制

Shell 命令执行是最高风险的权限之一。允许命令白名单指定哪些命令可以执行：

```yaml
security:
  commands:
    whitelist:
      - git
      - docker
      - python
      - pip
      - npm
    blacklist:
      - rm -rf /
      - chmod -R 777
    require_confirmation:
      - sudo
      - apt-get
      - yum
    max_execution_time: 300
    max_output_size: 10MB
```

危险命令拦截检测并阻止可能造成损害的命令，如删除根目录、清空日志等操作。执行超时防止命令无限运行。输出大小限制防止命令产生过多输出耗尽资源。

### 4.4 工具使用审批

某些高风险工具在执行前需要审批流程。审批工作流：用户尝试执行工具 → 系统标记需要审批 → 通知审批者 → 审批者批准或拒绝 → 根据结果执行或拒绝。配置审批规则：

```yaml
security:
  approval:
    rules:
      - tool: run_command
        condition: "command contains 'sudo' or 'rm'"
        approvers:
          - admin@company.com
        timeout: 3600
      
      - tool: write_file
        condition: "path starts_with '/etc' or path starts_with '/root'"
        approvers:
          - admin@company.com
        timeout: 1800
```

审批通知可以通过邮件、Slack 等渠道发送。超时未审批视为拒绝。

## 五、数据保护

### 5.1 敏感信息处理

Hermes Agent 自动识别和处理敏感信息，防止泄露。敏感信息模式识别：API 密钥格式（如 `sk-xxx`、`api_key=xxx`）、密码格式、私钥格式、信用卡号码、社会安全号码等。识别到的敏感信息会被自动脱敏，不会出现在日志或导出文件中。脱敏处理将敏感内容替换为 `[REDACTED]` 或部分遮蔽的内容如 `sk-****`（只显示前4位）。配置文件中的敏感字段使用加密存储，使用主密钥进行保护。环境变量中的敏感信息不会通过错误消息暴露。

### 5.2 加密存储

敏感数据在存储时进行加密。加密范围包括配置文件中的 API 密钥、会话数据中的敏感内容、插件存储的凭证信息。加密算法使用 AES-256-GCM，提供认证加密确保数据完整性和机密性。密钥管理主加密密钥由用户设置密码派生而来，建议使用强密码。可以使用外部密钥管理服务（KMS），如 AWS KMS、HashiCorp Vault 等，提高密钥安全性。密钥轮换定期更换加密密钥，更换时重新加密已有数据。加密验证系统启动时验证加密功能正常，加密数据可以被正确解密。

### 5.3 数据备份与恢复

数据备份是防止数据丢失的重要措施。自动备份配置备份计划：

```yaml
backup:
  enabled: true
  schedule: "0 2 * * *"  # 每天凌晨2点
  retention_days: 30
  destination: /backups/hermes
  compress: true
  encrypt: true
```

备份内容包括配置文件、会话数据、记忆存储、审计日志等。备份加密确保备份文件本身的安全性。恢复测试定期验证备份可以成功恢复，确保备份有效。异地备份将备份存储在不同地理位置，防止本地灾难导致数据丢失。备份监控监控备份任务状态，失败时发送告警。

### 5.4 数据保留策略

数据保留策略控制数据的生命周期。自动清理过期数据：

```yaml
data_retention:
  sessions:
    max_age_days: 90
    max_count: 1000
  
  audit_logs:
    max_age_days: 180
  
  memories:
    max_age_days: 365
  
  cache:
    max_age_hours: 24
```

超过保留期限的数据会被自动删除。保留例外可以对重要会话或数据设置永久保留。删除操作支持安全擦除，多次覆写确保数据不可恢复，符合合规要求。

## 六、审计与监控

### 6.1 审计日志

审计日志记录所有安全相关事件。日志内容包括认证事件（登录、登出、认证失败）、权限检查（权限授予和拒绝）、敏感操作（文件写入、命令执行）、配置变更（用户、角色、权限的修改）、系统事件（启动、关闭、错误）。日志格式采用结构化格式，便于解析和分析：

```json
{
  "timestamp": "2024-01-15T10:30:45Z",
  "level": "INFO",
  "event": "permission_check",
  "user": "alice",
  "action": "tool:run_command",
  "result": "denied",
  "reason": "command not in whitelist",
  "ip": "192.168.1.100"
}
```

日志保护日志本身是防篡改的，任何修改都会被检测到。日志归档定期将日志归档到冷存储，降低存储成本同时满足合规保留要求。

### 6.2 安全监控

实时安全监控检测和响应安全事件。监控指标包括失败登录次数、异常命令执行、权限拒绝频率、敏感数据访问等。告警规则设置：

```yaml
security:
  alerts:
    - name: brute_force
      condition: "failed_logins > 5 in 10 minutes"
      severity: high
      action: notify + lock_account
    
    - name: privilege_escalation
      condition: "role_change detected"
      severity: critical
      action: notify + block_user
```

告警通知通过邮件、Slack、Webhook 等渠道发送。自动响应某些告警可以触发自动响应，如临时锁定账户。监控仪表板提供安全状态的可视化概览。

### 6.3 合规报告

合规报告满足监管和审计需求。自动生成合规报告包括访问控制摘要、权限变更历史、异常事件列表、数据保留情况等。报告格式支持 PDF、CSV、JSON 等。合规框架对齐可以生成符合特定标准的报告，如 SOC 2、GDPR、ISO 27001 等。报告分发定期向相关人员发送报告，如每周安全报告。审计追踪提供完整的操作证据链，满足合规调查需求。

## 七、最佳实践

### 7.1 安全配置建议

强化安全配置的建议包括：使用强密码策略，要求足够长度和复杂性；启用多因素认证增加账户安全性；限制管理员角色成员数量，遵循最小权限原则；定期审查用户和权限配置，移除不必要的访问；配置网络限制，减少攻击面；启用审计日志，记录所有安全相关事件；定期更新系统，获取安全补丁；配置自动备份，防止数据丢失。

### 7.2 日常安全检查

日常安全检查清单包括：查看审计日志中的异常事件；检查活跃会话列表，终止可疑会话；查看权限变更记录；检查备份任务状态；更新系统和插件到最新版本；审查插件来源和权限需求；检查 API 密钥使用情况；验证加密功能正常工作。建议将日常检查纳入定期工作流程。

### 7.3 应急响应

安全事件发生时的响应流程：隔离评估确定事件范围和影响；遏制措施阻止进一步损害，如断开网络或锁定账户；调查分析确定事件原因和过程；恢复修复清除威胁并恢复正常服务；事后复盘总结经验教训改进防御。应急响应计划应该预先制定并定期演练。保留证据供事后分析和法律需要。
