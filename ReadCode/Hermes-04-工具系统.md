# Hermes Agent 使用指南 04：工具系统篇 - 工具使用与自定义工具

## 一、工具系统概述

### 1.1 工具系统的定位与作用

Hermes Agent 的工具系统是框架最核心的扩展机制之一，它使得 Agent 能够超越单纯的文本生成，与外部世界进行实质性的交互。在没有工具的情况下，Agent 只是一个强大的文本生成器；而有了工具系统，Agent 就变成了一个能够执行实际操作、完成复杂任务的智能助手。工具系统的工作原理是：当 Agent 分析用户请求时，会判断是否需要调用工具以及调用哪些工具，然后生成结构化的调用指令，系统接收指令后执行相应的操作，最后将结果返回给 Agent 进行整合。这种设计将 AI 的推理能力与工具的执行能力有机结合，实现了「思考」与「行动」的统一。工具可以是简单的单函数，如获取当前时间；也可以是复杂的系统，如完整的代码执行环境。

### 1.2 工具的分类体系

Hermes Agent 的工具按照功能可以分为多个类别，每个类别承担不同的职责。第一类是文件系统工具，负责文件的读取、写入、修改、搜索等操作，是日常工作中最常用的工具之一。第二类是网络工具，包括 HTTP 请求、网页抓取、API 调用等，使 Agent 能够获取互联网上的信息。第三类是代码执行工具，支持运行各种编程语言的代码，实现动态计算和程序验证。第四类是系统工具，提供执行 shell 命令、操作进程、管理服务等功能。第五类是数据处理工具，包括 JSON 解析、正则表达式匹配、数据格式转换等。第六类是专业领域工具，如数据库操作、云服务接口等。每个类别都有统一的设计规范和安全边界，确保工具的安全可控。工具还可以按照来源分类：内置工具是框架自带的核心工具，社区工具来自插件生态，自定义工具由用户自行开发。

### 1.3 工具调用的生命周期

理解工具调用的生命周期有助于更好地使用和调试工具。生命周期包括以下阶段：首先是发现阶段，系统在启动时扫描并注册所有可用的工具，建立工具目录；然后是匹配阶段，Agent 分析用户意图，从目录中选择最合适的工具；接着是验证阶段，系统检查调用参数是否符合工具的模式定义，并验证权限；执行阶段是实际运行工具代码，可能涉及网络通信、文件操作等；结果阶段收集工具输出，进行格式化和错误处理；最后是整合阶段，Agent 将工具结果纳入回复生成过程。每个阶段都有完善的日志记录和错误处理机制，如果某个阶段出现问题，系统会给出清晰的错误信息和修复建议。开发者可以针对生命周期的不同阶段添加钩子（Hooks），实现自定义的扩展逻辑。

## 二、内置工具详解

### 2.1 文件系统工具

文件系统工具是日常使用中最基础的工具集，主要包括以下几个核心工具。`ReadFile` 工具用于读取文件内容，支持指定编码和读取行数范围，适合查看文件的部分内容。`WriteFile` 工具用于创建或覆盖文件内容，支持文本和二进制模式，写入时可以选择是否自动创建父目录。`EditFile` 工具是更精细的编辑工具，支持在文件中插入、删除或替换内容，常用于代码修改。`ListDirectory` 工具列出目录内容，支持递归遍历和过滤选项。`SearchFiles` 工具在文件内容中进行正则表达式搜索，返回匹配的行和位置信息。`FileInfo` 工具获取文件的元数据，包括大小、创建时间、权限等信息。使用这些工具时需要注意路径的处理，默认情况下使用相对路径会基于当前工作目录，也可以使用绝对路径或波浪号（~）表示用户主目录。

### 2.2 网络与信息获取工具

网络工具使 Agent 能够访问互联网和调用外部服务。`HTTPRequest` 是最基础的网络工具，支持 GET、POST、PUT、DELETE 等 HTTP 方法，可以发送自定义头部和请求体。`WebSearch` 工具提供便捷的搜索引擎查询功能，返回搜索结果摘要。`WebFetch` 工具抓取指定网页的内容并进行初步解析。`APIRequest` 是对 HTTPRequest 的高级封装，针对 RESTful API 的常见模式进行了优化。`JSONQuery` 工具用于从 JSON 响应中提取特定字段，简化数据处理。使用这些工具时，系统会自动处理常见的网络问题，如重定向、超时等。同时，所有的网络请求都会被记录和审计，确保安全合规。对于需要认证的 API，系统支持多种认证方式，包括 API Key、OAuth2、Bearer Token 等，可以在配置中预设凭证信息。

### 2.3 代码执行工具

代码执行工具让 Agent 能够动态运行代码，是实现复杂计算和程序验证的关键。`RunPython` 工具执行 Python 代码，支持指定代码版本和依赖包。`RunBash` 工具执行 Shell 命令，返回标准输出和标准错误。`RunJavaScript` 工具在 Node.js 环境中执行 JavaScript 代码。代码执行工具都运行在隔离的环境中，具有资源限制和安全边界，防止恶意代码造成损害。执行超时可以配置，默认是 30 秒。内存使用也有限制，避免无限循环消耗资源。工具会捕获并返回执行结果、错误信息和性能指标。对于 Python 代码，还可以指定工作目录和导入额外的模块。代码执行工具特别适合动态计算、算法验证、数据处理和快速原型开发等场景。

### 2.4 其他内置工具

除了上述主要工具类别，Hermes Agent 还提供了许多辅助工具。`GetTime` 工具返回当前时间，支持多种时区和格式。`Calculate` 工具进行数学表达式计算，支持复杂函数。`GenerateUUID` 工具生成唯一的标识符。`HashCalculate` 工具计算字符串或文件的哈希值。`Base64Encode` 和 `Base64Decode` 工具处理 Base64 编解码。`RegexMatch` 工具进行正则表达式匹配和提取。`JSONParse` 和 `JSONFormat` 工具处理 JSON 数据的解析和格式化。这些工具虽然功能单一，但在日常使用中非常实用，可以大大提高工作效率。所有内置工具都经过充分测试和优化，确保稳定可靠。工具的帮助文档可以在 CLI 中通过 `help <tool_name>` 查看，包括功能说明、参数定义和使用示例。

## 三、工具配置与管理

### 3.1 工具启用与禁用

工具的启用和禁用可以通过配置进行控制。在 `config.yaml` 的 `tools` 部分，可以设置全局的 `enabled` 开关来启用或禁用整个工具系统。更细粒度的控制可以通过 `allowed_categories` 和 `blocked_tools` 实现，前者指定允许使用的工具类别，后者列出明确禁用的特定工具。临时启用或禁用工具也很方便，某些启动参数可以在运行时覆盖配置设置。工具的可用性还受到权限级别的限制，普通用户可能无法使用管理员级别的工具。关于权限管理的详细内容将在后续章节介绍。合理配置工具的可用性是安全策略的重要组成部分，应该遵循最小权限原则，只启用确实需要的工具。

### 3.2 工具参数配置

每个工具都有可配置的参数，用于调整其行为。以 `HTTPRequest` 工具为例，可以配置默认超时时间、重试次数、代理设置等。这些参数可以在配置文件的 `tools` 部分统一设置，也可以针对单个工具设置。工具参数支持默认值和覆盖值的设计，当没有显式指定时使用默认值，可以在调用时覆盖的部分使用覆盖值。某些工具还支持动态参数，在调用时根据上下文自动确定。参数验证在执行前进行，确保参数类型正确、值在有效范围内。对于复杂的工具参数，系统提供参数文档和补全支持，帮助用户正确配置。工具参数的配置应该参考各工具的官方文档，了解每个参数的含义和推荐值。

### 3.3 工具使用审计

工具使用审计是安全运营的重要组成部分。系统默认记录所有工具调用的详细日志，包括调用时间、调用者身份、工具名称、输入参数和执行结果。这些日志对于问题排查、行为分析和合规审计都非常有价值。日志配置控制记录的内容详细程度和保留时长，可以根据安全需求进行调整。敏感操作如文件写入、系统命令执行等会有额外的日志级别和告警机制。审计日志可以导出为多种格式，便于集成到外部的 SIEM 系统或日志分析平台。定期审查工具使用日志是发现异常行为和潜在安全风险的有效手段。某些受监管行业可能有强制性的审计要求，工具审计功能可以帮助满足这些合规性要求。

## 四、自定义工具开发

### 4.1 工具开发基础

创建自定义工具需要遵循框架定义的接口规范。工具本质上是一个 Python 函数或类，具有特定的签名和元数据。基本的工具函数接收参数字典作为输入，返回执行结果或错误信息。工具还需要提供元数据定义，包括工具名称、描述、参数模式和返回值模式等。参数模式采用 JSON Schema 格式定义，描述每个参数的名称、类型、是否必填、默认值和约束条件。返回值模式描述正常返回和可能的错误情况。框架会根据这些定义自动生成工具的使用说明和参数补全。开发自定义工具需要具备一定的 Python 编程能力，了解装饰器（Decorator）的使用方式，以及 JSON Schema 的基本语法。

### 4.2 工具注册机制

开发完成的工具需要注册到系统中才能被使用。注册有两种方式：代码注册和配置文件注册。代码注册通过 `@hermes_tool` 装饰器标记工具函数，系统启动时自动扫描并注册。装饰器可以接受参数来配置工具的元数据，如名称、描述、示例等。配置文件注册将工具信息写入 YAML 配置文件，指定工具的模块路径和类名/函数名，系统启动时根据配置动态导入和注册。两种方式各有优缺点：代码注册更集中，便于管理；配置注册更灵活，无需修改代码。注册时系统会验证工具定义的完整性，检查参数模式和返回值模式是否有效。如果注册失败，系统会报告具体原因，帮助开发者定位问题。已注册的工具可以通过 `hermes tools list` 命令查看。

### 4.3 工具代码示例

以下是一个简单的自定义工具示例，实现获取系统信息的功能。首先定义工具函数：

```python
from hermes.tools import hermes_tool
from hermes.tools.params import Param, ParamType

@hermes_tool(
    name="get_system_info",
    description="获取系统信息，包括操作系统、CPU、内存等",
    category="system"
)
def get_system_info(
    include_network: bool = Param(
        default=False,
        description="是否包含网络配置信息"
    )
) -> dict:
    """获取系统信息的工具函数"""
    import platform
    import psutil
    
    info = {
        "os": platform.system(),
        "os_version": platform.version(),
        "architecture": platform.machine(),
        "cpu_count": psutil.cpu_count(),
        "cpu_percent": psutil.cpu_percent(interval=1),
        "memory_total": psutil.virtual_memory().total,
        "memory_available": psutil.virtual_memory().available,
        "memory_percent": psutil.virtual_memory().percent
    }
    
    if include_network:
        info["network"] = {
            iface: {
                "addresses": addrs,
                "is_up": psutil.net_if_stats().get(iface, None) and psutil.net_if_stats()[iface].isup
            }
            for iface, addrs in psutil.net_if_addrs().items()
        }
    
    return info
```

这个示例展示了工具开发的基本结构：装饰器定义元数据、参数定义、函数实现和返回值。

### 4.4 工具的错误处理

健壮的错误处理是高质量工具的标志。工具函数应该使用标准的异常类型，并在适当的地方进行 try-except 包装。框架定义了多种专用异常类型，如 `ToolExecutionError` 表示执行失败、`InvalidParameterError` 表示参数错误、`PermissionDeniedError` 表示权限不足等。工具应该在异常发生 时提供有意义的错误信息，帮助调用者理解问题原因。避免暴露敏感的内部实现细节，只在错误信息中包含必要的信息。同时，应该记录详细的错误日志供事后分析。对于可能超时的操作，应该实现超时检测和取消机制。工具执行的结果应该是确定性的，相同的输入总是产生相同的输出，这对于测试和调试非常重要。

## 五、工具的高级特性

### 5.1 工具依赖管理

复杂的工具可能依赖外部的 Python 包或系统资源。Hermes Agent 提供了完善的依赖管理机制。工具可以在元数据中声明所需的 Python 包，系统在首次执行前检查依赖是否满足，如果不满足会提示安装。对于无法自动安装的依赖，系统会给出清晰的安装指引。工具还可以声明系统依赖，如特定的命令行工具或系统库，这些通常需要在系统层面预先安装。懒加载机制确保依赖只在需要时才加载，避免启动时的性能开销。依赖版本约束确保工具运行在兼容的环境中，某些工具可能对依赖版本有特定要求。依赖冲突检测帮助避免多个工具对同一包的不同版本需求造成冲突。

### 5.2 工具组合与管道

工具可以组合使用，实现更复杂的工作流程。工具管道（Pipeline）将多个工具串联起来，前一个工具的输出作为后一个工具的输入。例如，先用 `WebSearch` 搜索信息，再用 `WebFetch` 获取详细内容，最后用 `JSONParse` 解析数据，整个流程可以自动串联执行。工具组合需要在配置中定义，明确输入输出的映射关系。条件执行允许根据前一步的结果决定下一步的操作，实现基本的流程控制。错误处理在管道中也很重要，某一步失败时可以决定是中断流程还是尝试备选方案。管道执行的结果会被完整记录，便于追踪和调试。工具组合特别适合自动化重复性任务，可以显著提升工作效率。

### 5.3 工具缓存与性能优化

对于频繁调用的工具，系统提供了缓存机制来减少重复执行。缓存策略包括基于输入的缓存（相同输入返回缓存结果）和基于时间的缓存（定期刷新）。缓存键由工具名称和输入参数共同决定，确保不同调用返回正确的结果。缓存可以配置过期时间和最大条目数，避免无限增长。工具执行性能也受到关注，对于耗时较长的工具，系统会显示执行进度。异步执行支持某些工具可以并行执行，充分利用多核 CPU。预热机制在空闲时预先加载常用工具到内存，减少首次调用的延迟。性能监控帮助识别慢工具，优化执行效率。

### 5.4 工具的安全沙箱

工具在隔离的沙箱环境中执行，这是安全保障的重要措施。沙箱限制了工具可以访问的资源，包括文件系统权限、网络访问范围、系统调用限制等。文件访问默认限制在用户指定的工作目录内，防止访问敏感文件。某些危险操作如删除系统文件、执行特权命令等被禁止。网络访问可以限制为仅允许访问白名单域名，防止数据泄露到恶意服务器。CPU 和内存使用有严格限制，防止恶意代码消耗系统资源。沙箱配置可以根据信任级别调整，高信任的工具可以获得更多权限，但也意味着更大的风险。安全审计追踪沙箱中的所有操作，记录访问了哪些文件、访问了哪些网络地址等。

## 六、工具生态与分享

### 6.1 工具市场与发现

Hermes Agent 维护着一个工具市场，用户可以在这里发现和安装社区开发的工具。工具市场展示工具的描述、功能预览、用户评分和安装量等 信息，帮助用户找到高质量的工具。搜索功能支持按名称、标签、功能描述进行搜索。工具详情页面提供完整的使用文档、示例代码和变更历史。评分和评论系统让用户分享使用体验，帮助其他人做出选择。官方认证的工具经过安全审核，有更高的可信度。工具开发者可以发布自己的作品，设置开源或商业授权。工具市场定期更新，推荐新发布和热门工具。

### 6.2 工具的导入导出

工具可以打包导出在其他环境或团队中共享。导出工具需要指定工具列表，系统会收集工具代码和依赖信息，生成一个工具包文件。工具包是一个压缩文件，包含工具代码、依赖清单、使用文档和元数据。导入工具只需指定工具包文件或市场中的工具 ID，系统会验证工具的签名和完整性，然后安装到本地。版本管理确保导入的工具与框架版本兼容，不兼容的工具会被标记警告。团队可以建立私有的工具仓库，托管内部开发的工具包，通过私有源进行分发。这种工具分发机制使得知识和最佳实践可以在团队内快速传播。

### 6.3 贡献工具到社区

如果你开发了一个有价值的工具，可以贡献给社区。首先需要准备工具的完整代码、测试用例和使用文档。然后在工具市场平台创建发布，填写工具的描述、标签和截图。发布前应该进行充分测试，确保工具在各种场景下都能正常工作。工具需要通过安全扫描，确保没有恶意代码或安全漏洞。审核团队会在 1-2 周内完成审核，之后工具就可以被其他用户发现和安装。持续维护工具很重要，包括修复问题、更新兼容性和添加新功能。建立社区反馈渠道，及时响应用户的问题和建议。优秀的工具开发者可以获得平台的认证和推荐，增加工具的曝光度。

## 七、最佳实践与案例

### 7.1 工具设计最佳实践

设计良好的工具应该具备以下特征。首先是单一职责，每个工具只做一件事，这样便于测试和维护。其次是清晰的接口，参数名称和返回值都有明确的语义，用户无需查看实现就能理解。完善的文档是不可或缺的，包括功能说明、参数解释、使用示例和注意事项。健壮的错误处理确保工具在异常情况下也能给出有用的反馈。一致的命名约定让工具集易于理解，遵循框架的命名规范。版本控制和语义化版本号帮助用户了解工具的变更历史。示例代码让新用户能够快速上手。

### 7.2 实用工具案例

让我们看几个实用工具的开发案例。第一个案例是天气查询工具，它调用天气 API 获取指定城市的天气信息。工具接收城市名称作为参数，返回温度、湿度、天气状况等信息。错误处理包括无效城市名和网络错误。第二个案例是数据可视化工具，它接收数据集并生成可视化图表。工具支持多种图表类型，如折线图、柱状图、散点图等，输出可以是图片或交互式 HTML。第三个案例是代码质量检查工具，它运行静态分析工具并汇总结果。工具执行多个检查器，合并并格式化输出，突出显示严重问题。这些案例展示了工具开发的典型场景和解决方案。

### 7.3 常见问题与解决

开发自定义工具时可能遇到一些常见问题。导入错误通常是因为 Python 模块路径问题或缺少依赖，确保工具文件在正确的包目录下，所有依赖都已安装。参数验证失败可能是因为传入的参数类型或值不符合模式定义，仔细检查参数类型和约束条件。工具注册失败可能是因为装饰器使用不当或元数据缺失，查看注册日志了解具体原因。执行超时可能是工具陷入了无限循环或等待，应该添加超时检测和合理的时间预算。安全问题被拦截可能是工具尝试了受限操作，调整沙箱配置或重新设计工具逻辑。性能问题可以通过添加缓存、优化算法或异步执行来解决。
