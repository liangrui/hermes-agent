# Hermes Agent 使用指南 01：入门篇 - 项目概述与快速安装

## 一、项目概述

### 1.1 什么是 Hermes Agent

Hermes Agent 是一个模块化的智能代理框架，旨在为用户提供强大而灵活的人工智能交互体验。该项目采用分层架构设计，将核心代理循环、工具系统、记忆管理、插件机制等关键组件进行解耦，实现了高度的可扩展性和可维护性。通过自注册和 AST 自动发现机制，Hermes Agent 能够动态识别和加载系统中的各类工具和插件，极大地提升了框架的灵活性。同时，项目引入 Curator 机制实现后台技能维护，并通过 Credential Pool 管理凭证信息，确保了系统的安全性和易用性。无论是日常对话、代码开发还是复杂任务自动化，Hermes Agent 都能提供稳定而高效的支持。

### 1.2 核心特性概览

Hermes Agent 的设计理念围绕三大核心原则展开：模块化、灵活性和安全性。在模块化方面，框架将功能划分为独立且职责明确的组件，包括核心代理循环（Conversation Loop）、工具注册中心（Tool Registry）、消息网关（Message Gateway）、记忆管理器（Memory Manager）等，每个组件都可以独立开发、测试和部署。在灵活性方面，支持多种 AI 模型提供商、自定义工具开发、热插拔插件机制以及可配置的对话策略。在安全性方面，实现了多层安全防护，包括命令审批流程、路径安全检查、敏感信息脱敏以及供应链安全验证，确保用户数据和系统安全。

### 1.3 技术架构简介

Hermes Agent 的整体架构可分为五个主要层次。第一层是交互界面层，提供 CLI 命令行界面和 TUI 文本界面两种交互方式，支持实时响应和流式输出。第二层是核心代理层，包含对话循环、上下文管理、工具调度和结果处理等核心逻辑。第三层是服务支撑层，负责消息路由、状态持久化、技能管理和日志记录等后台服务。第四层是扩展机制层，支持插件发现注册、模型提供商适配和外部工具集成。第五层是基础设施层，提供配置加载、凭证管理、环境检测和依赖解析等基础能力。这种分层设计不仅便于理解和维护，也为未来的功能扩展奠定了坚实基础。

## 二、系统要求与环境准备

### 2.1 硬件与系统要求

Hermes Agent 对运行环境有明确的要求，以确保系统能够稳定运行。在硬件方面，推荐使用具有至少 8GB 内存的系统，如果需要运行大型语言模型，建议配置 16GB 或以上内存。存储空间方面需要至少 10GB 的可用磁盘空间，用于安装依赖、存储模型缓存和保存会话数据。GPU 支持是可选的，但如果你计划使用本地部署的模型，拥有 NVIDIA GPU 将显著提升推理速度。在操作系统方面，Hermes Agent 支持 Linux、macOS 和 Windows（通过 WSL2）三大平台，其中 Linux 是生产环境的首选，macOS 适合日常开发和测试，Windows 用户建议通过 WSL2 获得最佳体验。

### 2.2 软件依赖安装

在安装 Hermes Agent 之前，需要确保系统中已安装必要的软件依赖。首先是 Python 环境，Hermes Agent 要求 Python 版本不低于 3.10，推荐使用 3.11 或更高版本以获得最佳性能和兼容性。你可以通过运行 `python --version` 命令来检查当前 Python 版本。其次是 pip 包管理器，确保其版本是最新的，可以通过 `pip install --upgrade pip` 命令进行升级。此外，对于某些可选功能，还需要安装 Git（用于克隆代码仓库）、Docker（用于容器化部署）以及 CUDA Toolkit（用于 GPU 加速）。在 Linux 系统上，可能还需要安装构建工具链来编译某些依赖包。

### 2.3 虚拟环境配置（推荐）

为了避免依赖冲突和保持项目环境的整洁，推荐使用虚拟环境来安装 Hermes Agent。Python 提供了多种虚拟环境管理工具，包括内置的 venv、pyenv 以及更高级的 poetry 和 pdm。以下是使用 venv 创建虚拟环境的步骤：首先创建并激活虚拟环境，然后在此环境中安装 Hermes Agent 及其依赖。使用虚拟环境的好处是能够为不同项目创建隔离的 Python 环境，每个环境都有独立的包版本和配置，互不干扰。当你需要同时处理多个项目或测试不同版本的 Hermes Agent 时，这种隔离机制尤为重要。

## 三、安装 Hermes Agent

### 3.1 方式一：通过 pip 直接安装

对于大多数用户来说，使用 pip 安装是最简便的方式。只需在终端中执行一条命令即可完成安装。如果需要安装包含所有可选依赖的完整版本，可以使用 `pip install hermes-agent[all]` 命令。pip 安装方式会自动处理所有 Python 依赖项，并创建必要的命令行入口脚本。安装完成后，你可以通过 `hermes --version` 命令验证安装是否成功。这种方式适合快速体验和一般使用场景，但需要注意的是，pip 安装的版本可能不是最新的开发版本，如果你需要使用最新特性或参与开发，可能需要选择其他安装方式。

### 3.2 方式二：从源码编译安装

从源码安装可以获得最大的灵活性，允许你查看和修改代码、定制功能以及使用最新的开发版本。首先需要克隆官方代码仓库，然后进入项目目录进行安装。在克隆仓库时，可以选择稳定版本分支或最新的开发分支。安装过程会使用 setuptools 构建包并安装所有依赖项。从源码安装还支持开发模式，使用 `pip install -e .` 命令可以创建可编辑安装，这样对代码的修改会立即生效，无需重新安装。如果你计划为项目贡献代码或需要深度定制功能，这种方式是你的首选。

### 3.3 方式三：使用 Docker 部署

Docker 为那些希望避免手动配置依赖的用户提供了一种便捷的部署方式。Hermes Agent 提供了官方的 Docker 镜像，其中包含了所有必要的运行环境。你可以使用 docker pull 命令拉取最新镜像，然后通过 docker run 命令启动容器。对于需要持久化配置和数据的情况，建议使用数据卷来挂载宿主机的目录。此外，Docker Compose 提供了一种声明式的部署方式，通过编写 docker-compose.yml 文件可以定义完整的服务拓扑，包括环境变量、端口映射和数据卷等。使用 Docker 的好处是环境完全隔离，一键部署，且易于在不同平台间迁移。

### 3.4 安装验证与环境诊断

安装完成后，运行诊断命令来验证系统配置是否正确。Hermes Agent 提供了内置的 doctor 命令，可以自动检测 Python 版本、依赖包状态、GPU 可用性以及配置文件的完整性。如果诊断过程中发现问题，命令会提供具体的修复建议，包括缺失依赖的安装命令和配置错误的修改方法。建议在首次安装后和进行重要配置修改后都运行一次诊断，确保系统处于最佳状态。此外，你还可以通过 `hermes plugins list` 命令查看已安装的插件列表，通过 `hermes models list` 命令查看可用的模型提供商配置。

## 四、快速开始

### 4.1 首次启动与配置向导

首次启动 Hermes Agent 时，系统会引导你完成基本的配置过程。配置向导会依次询问以下内容：选择默认的 AI 模型提供商、配置 API 密钥（如果使用第三方模型）、设置工作目录路径以及选择安全策略等级。这些配置会被保存在用户配置文件中，供后续启动时加载。如果你在首次启动时选择跳过配置向导，也可以随时通过 `hermes config init` 命令重新运行向导，或直接编辑配置文件进行修改。配置文件采用 YAML 格式，结构清晰易于理解，你可以在编辑器中直接修改各项参数。

### 4.2 第一个对话示例

完成基本配置后，就可以开始第一次对话了。启动交互式会话只需在终端中执行 `hermes` 命令，不带任何参数。系统会显示欢迎信息和状态栏，然后等待你的输入。试着输入一些简单的问候或问题，观察 Agent 的响应方式和输出格式。在对话过程中，你可以随时使用帮助命令（通常是通过输入 help 或 ?）查看可用的命令和操作。默认情况下，对话会保持上下文连贯性，Agent 能够记住之前的交流内容。如果你希望开始一个全新的对话，可以使用 reset 命令清除历史记录。尝试几个不同的对话场景，感受 Agent 的响应风格和能力边界。

### 4.3 基本命令操作

Hermes Agent 的命令行界面提供了一系列实用命令来提升使用效率。`/help` 命令用于显示所有可用命令及其简要说明。`/model` 命令允许你在不同模型之间切换，而无需退出当前会话。`/context` 命令显示当前对话的上下文状态和 token 使用情况。`/save` 命令将当前对话保存为可复用的模板，方便以后快速加载类似场景。`/export` 命令支持将对话记录导出为 Markdown、JSON 或纯文本格式。对于复杂任务，`/plan` 命令可以帮你分解问题为可执行的步骤序列。掌握这些基础命令能够显著提升使用效率和体验。

### 4.4 退出与状态保存

当你需要结束对话时，可以使用 `exit` 或 `quit` 命令安全退出。Hermes Agent 会在退出前自动保存对话状态和用户偏好设置，下次启动时会恢复到上次离开时的状态。如果你希望显式保存当前状态而不退出，可以使用 `Ctrl+S` 快捷键或执行 `/save session` 命令。在某些情况下，可能需要强制退出，此时可以使用 `Ctrl+C` 组合键，但这种方式不会保存未保存的状态。需要注意的是，Hermes Agent 的状态保存机制依赖于配置的存储路径，确保该路径有适当的写入权限，否则状态信息将无法正确保存。

## 五、架构总览

### 5.1 核心组件关系

Hermes Agent 的各个组件之间通过明确定义的接口进行通信，形成了有机协作的整体。CLI 界面作为用户交互的入口，接收用户输入并格式化后传递给核心代理。核心代理（Agent）负责管理对话循环，调用工具系统执行具体任务，并通过记忆系统维护上下文。工具系统提供 Agent 与外部世界交互的能力，包括文件操作、网络请求、代码执行等。插件系统则允许扩展框架的功能边界，添加新的工具或集成第三方服务。消息网关负责协调各组件之间的通信，确保信息传递的可靠性和顺序性。理解这些组件之间的关系有助于更好地使用框架和排查问题。

### 5.2 配置系统层次

Hermes Agent 采用分层配置机制，平衡了系统默认配置和用户个性化需求。配置层次从高到低依次为：命令行参数（最高优先级）、用户配置文件、项目配置文件和系统默认配置。当存在冲突时，高层配置会覆盖低层配置。用户配置文件通常位于用户主目录下的隐藏文件夹中（`.hermes`），项目配置文件则放在当前工作目录或指定的配置目录中。这种设计允许你在不同项目中使用不同的配置，同时保持用户级别的偏好设置一致。配置系统还支持环境变量覆盖，通过 `HERMES_` 前缀的环境变量可以临时修改配置，常用于容器化部署场景。

### 5.3 扩展机制概述

Hermes Agent 的扩展性是其核心优势之一。框架提供了多种扩展点，允许开发者以不同方式增强系统功能。工具扩展点允许添加自定义功能模块，通过实现特定的接口并注册到工具中心，即可让 Agent 调用新的能力。模型扩展点支持集成新的 AI 模型提供商，只需实现模型适配器接口，即可让框架使用不同的语言模型。插件扩展点是更高级的扩展方式，插件可以包含多个工具、配置选项和依赖项，通过声明式的方式定义完整的功能包。此外，Hermes Agent 还支持事件钩子（Hooks），允许你在特定操作执行前后插入自定义逻辑，实现更细粒度的控制。

## 六、常见问题与解决方案

### 6.1 安装过程中常见问题

在安装 Hermes Agent 时，可能会遇到一些常见问题。第一个常见问题是 Python 版本不兼容，错误信息通常提示需要的 Python 版本，此时需要升级 Python 或创建使用正确 Python 版本的虚拟环境。第二个常见问题是依赖包安装失败，可能是因为网络连接问题或系统缺少编译工具，建议使用国内镜像源或安装必要的系统依赖。第三个常见问题是权限错误，在某些系统上需要使用管理员权限或调整目录权限才能完成安装。第四个常见问题是 Docker 镜像拉取失败，可能是因为 Docker 配置问题或网络限制，此时可以尝试更换镜像源或使用代理。

### 6.2 首次启动常见问题

首次启动 Hermes Agent 时也可能遇到一些问题。如果启动后立即报错退出，首先检查配置文件是否有语法错误，YAML 格式对缩进和标点非常敏感。如果是 API 密钥相关错误，确保密钥配置正确且具有相应的访问权限。对于模型连接超时的问题，可能需要检查网络设置或更换模型端点。如果遇到 GPU 相关错误，确认 CUDA 驱动已正确安装且版本兼容。当出现权限被拒绝的错误时，检查工作目录的读写权限是否正确设置。如果问题仍然存在，可以查看详细的日志输出，使用 `--verbose` 参数可以获取更详细的调试信息。

### 6.3 环境诊断与自检

Hermes Agent 提供了完善的自我诊断功能，帮助用户快速定位和解决问题。运行 `hermes doctor` 命令可以执行全面的环境检查，包括 Python 版本验证、依赖包状态检查、配置文件有效性验证以及网络连接测试。诊断结果会以列表形式展示，每项都会标注通过或失败状态。对于失败的项目，会提供具体的问题描述和修复建议。此外，`hermes info` 命令可以显示当前系统的完整配置信息，方便在寻求帮助时提供环境详情。如果你计划报告问题或寻求技术支持，首先运行诊断命令并将结果一并提供，会大大加快问题解决的速度。
